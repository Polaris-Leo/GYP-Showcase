# 鸽一品 / GEYIPIN 周边展厅 — 项目说明与部署指南

> 目标形态：**静态站托管 + 边缘函数 + KV 存储**，后台 `admin.html` 在线可视化编辑，
> 改动直接写入线上 KV，**所有访客刷新即可见**。不需要服务器，不需要构建步骤。

---

## 1. 为什么是这个方案（而不是 B 或 C）

之前给过三个选项，这里是最终结论：

| 方案 | 在线可视化编辑 | 需要维护服务器 | 改完是否立刻对所有访客生效 | 结论 |
|---|---|---|---|---|
| **A** 纯静态、删掉后台 | ✗ 改 HTML | ✗ | — | 放弃：失去编辑能力 |
| **B** 数据文件 + 后台导出文件 | △ 编辑是可视化的，但要下载文件→提交→等重新部署 | ✗ | ✗ 要重新部署 | 放弃：不算「在线编辑」 |
| **C** Node + Express 自建后端 | ✓ | ✓ 要买机器、装环境、盯进程、配 HTTPS | ✓ | 放弃：EdgeOne 已经白送同等能力 |
| **D** EdgeOne Pages + Functions + KV ← **采用** | ✓ | ✗ 全托管 | ✓ 即时 | **最合适** |

**为什么 D 优于 C**：你本来就要用 EdgeOne 部署。EdgeOne Pages 自带边缘函数和 KV 键值存储，
等于后端已经包含在托管里了。自建 Node 服务只是把同样的功能挪到一台需要你自己运维的机器上，
还多出机器成本、HTTPS 证书、进程守护、备份这些活儿。

**关键设计：静态优先，接口只做增强。**
两个展示页的默认内容仍然**硬编码在 HTML 里**，页面加载后才异步请求 `/api/content` 覆盖。
所以即使 KV 没绑定、函数挂了、或者你直接双击本地文件打开，页面依然是完整好看的——
不会白屏，不会「加载中」。这一点是从原来 localStorage 版本继承下来的保证，特意保留了。

## 4. 内容存储：从 localStorage 换成 KV

### 改造前
后台把内容写进浏览器的 `localStorage['gyp-admin-overrides']`。
问题：只有**你这台电脑的这个浏览器**能看到改动，访客看到的永远是默认内容；清缓存就丢。

### 改造后
```
admin.html  ──POST /api/content──▶  边缘函数  ──put──▶  EdgeOne KV
                                                          │
展示页  ──GET /api/content───────▶  边缘函数  ──get──────┘
```

- 内容的唯一存放点是 **KV**，全站共享。
- 项目里**已无任何 `localStorage`**（三个页面 grep 结果为 0）。
- `sessionStorage` 只用来暂存**管理口令**，关掉标签页即失效，与内容存储无关。

### 后台的三种连接状态

右上角有状态徽标，一眼看出当前能不能存：

| 徽标 | 含义 | 能否保存 |
|---|---|---|
| `● 已连接线上`（蓝） | 接口正常，口令有效 | ✓ 自动保存 |
| `● 需要口令`（黑） | 接口正常，但口令没填或不对 | ✗ 点「解锁」输入口令 |
| `● 离线（改动不会保存）`（红） | 接口不可用（本地打开 / KV 未绑定） | ✗ **仅本地预览** |

这个徽标是特意加的：原来的版本在保存失败时几乎没有提示，容易让人以为改动生效了。
现在离线状态下侧栏也会写明「当前仅本地预览，改动不会保存」。

### 保存行为

- 输入后 **400ms 防抖**自动保存（原来是 300ms，因为现在是网络请求，稍微放宽）。
- 保存**串行化**：一次请求还没回来时，后续改动会合并进下一次请求，
  避免并发写入互相覆盖（KV 没有事务，这一步是必要的）。
- 「数据」页的导出／导入**保留**了，但定位变了：现在是**备份与迁移**工具，
  不再是跨设备同步的唯一手段。导入会立刻覆盖线上内容。
- 保存成功后会**自动回收**不再被引用的已上传图片，见 §7「配额与清理」。
  这也意味着**导入一份不含某些图的旧备份，会把那些图从 Blob 里删掉** ——
  所以「导入并应用」和「恢复默认」都有确认弹窗，且导入的弹窗会**先算出具体会删几张、
  列出键名**再问。

### 后台列表的分页（每页 4 项）

「周边物品」和「历史条目」两个可增删列表在**超过 4 项时**才在列表末尾长出分页条，
4 项及以内完全看不出变化。三处容易踩空的地方已经处理：

| 操作 | 如果不处理会怎样 | 现在的行为 |
| --- | --- | --- |
| 添加物品 | 新条目追加在末尾、落在最后一页；停在第 1 页的话 DOM 里根本没有这个块，随后的滚动和聚焦静默失效 —— 看起来就是「按钮坏了」 | 自动翻到新条目所在页并聚焦它 |
| 上移／下移 | 跨页边界时（第 5 项上移成第 4 项）条目从当前页消失，像「按了一下东西没了」 | 跟着条目翻页 |
| 删除／导入更短的备份 | 当前页码越界，显示空白页 | 页码夹回有效范围 |

另外条目编号（01 / 02 …）和首尾条目的「上移／下移」禁用状态一律**按全局算**，
不按页内算 —— 否则第 2 页的第一项会显示成 01，它的「上移」还会被错误地变灰。
序号由 `buildItemBlock` 写在 `data-item-index` 上，`syncBlockTitle` 读它而不是反推
DOM 位置（分页后一页只有 4 个块，反推出来是 0～3）。

三个页大小互不相干，别记混：**后台编辑列表 4 项**、首页展厅 4 件
（`index.html` 的 `PAGE_SIZE`）、历史展厅展示页 3 条
（`history-archive.html` 的 `listPageSize` / `gridPageSize`）。

回归测试：`tests/admin-pager-test.js`（切真源码跑，95 条断言）。

## 5. 部署步骤

> 本节的具体 API 形态以官方文档为准，见 `functions/api/content.js` 顶部注释。

1. **创建 Pages 项目**：EdgeOne 控制台 → Pages → 新建项目，
   指向这个仓库（或直接上传 `site/` 目录）。构建命令留空，输出目录为站点根目录。

2. **创建并绑定 KV 命名空间**：控制台创建一个 KV 命名空间，
   在 Pages 项目的「KV 绑定」里把它绑到变量名 **`GYP_CONTENT`**。
   > 函数里读的就是这个名字。改名的话 `functions/api/content.js` 顶部的 `KV_BINDING` 要同步改。

3. **设置管理口令**：在 Pages 项目的环境变量里加
   **`ADMIN_TOKEN`** = 你自己定的一串口令。
   > 没设这个变量时，函数会**拒绝所有写入**（而不是放行），避免后台裸奔。

4. **把「安装命令」设为 `npm install`**（只有要用图片上传功能时才需要）。
   控制台 → 构建部署配置 → 安装命令。当前配置里这一项是**未设置**，
   意味着构建阶段不会安装依赖，于是：
   - `node_modules/@edgeone/pages-blob` 不存在 → `functions/img.js` 等三个函数导入失败；
   - Blob SDK 的凭据是**构建时替换进包里的占位符**，不装依赖就永远不会被替换。

   > 框架预设 `Other`、编译命令与输出目录都未设置，说明平台是把 `./` 直接当静态站点发布。
   > 加上 `package.json` 不会改变这一点（它里面**故意没有 `scripts` 字段**，
   > 平台无从推断出一个构建步骤），只是让安装依赖成为可能。

5. **部署**，然后打开 `https://<你的域名>/admin.html`，
   点右上「解锁」输入口令 → 改内容 → 打开首页确认生效。

### 自查清单

- [ ] `/api/content` 直接用浏览器打开，返回 JSON（首次是 `{}`）而不是 404 → 函数生效了
- [ ] 后台徽标显示「● 已连接线上」→ KV 绑定成功
- [ ] 改一个标题保存，无痕窗口打开首页能看到 → 全站生效
- [ ] 不填口令时保存报「口令不正确或已失效」→ 鉴权生效
- [ ] 后台「图片链接」下方出现「上传图片」按钮，选一张 PNG 能上传成功 → Blob 生效（见 §7 的验证清单）

## 6. 安全说明（请务必看一眼）

- 口令是**单一共享口令**，通过 `X-Admin-Token` 头传输。全站 HTTPS，传输安全。
  但这是「够用」级别，不是「企业级」：没有账号体系、没有登录失败限流、没有操作日志。
  对一个个人周边展示站是合理的取舍；如果以后要多人协作或内容重要度上升，需要升级鉴权。
- `admin.html` 本身是**公开可访问**的静态页面——任何人都能打开它看到界面。
  保护的是**写入接口**，不是页面。别人打开后台只能看，不能存。
  如果连界面都不想暴露，需要在 EdgeOne 侧加访问控制（如 IP 白名单或 Basic Auth）。
- **`ADMIN_TOKEN` 只存在服务端环境变量里**，不要写进任何 HTML 或提交进仓库。
- 上传接口（`/api/upload`、`/api/blobs`）**要求已登录**。这不是洁癖：不鉴权就等于
  把一个 1 GB 的写入口敞开给所有人。`/img` 是唯一公开的那个，它只读、且只认
  上传接口生成的那种键名（见 §7）。
- **不接受 SVG 上传**。SVG 可以内嵌 `<script>`，而它会从本站同源加载，
  等于给自己开一个存储型 XSS 入口。想用矢量图请先转成 PNG。

## 7. 大文件存储：Pages Blob

图片原本只能填外部直链（§3）。加上 Blob 之后多了一条路：在后台直接选文件上传，
拿到一个本站链接。**两条路并存**——「选择图片」弹窗底部始终留着「外部链接」输入框，
手填任意外部图片直链照样有效，上传只是帮你把链接填进去而已。
所以万一 Blob 出问题，原来的用法一点没受影响。

### 存储桶与键名

- 桶名 `gyp-assets`（三个函数顶部的 `STORE_NAME`，改要一起改）。
- 键名形如 `img/<内容 SHA-256 前 32 位>.<png|jpg|webp|gif>`，**由内容决定，不用原文件名**：
  1. 同一张图重复上传不会产生第二份，也不会互相覆盖出错（幂等）；
  2. 内容变了键名必然变 → `/img` 可以放心宣布缓存一年 `immutable`；
  3. 原文件名里的中文、空格、路径分隔符都进不到键里，省掉一整类转义问题。

### 三个接口

| 接口 | 鉴权 | 作用 |
|---|---|---|
| `POST /api/upload` | 需要 | 代理上传：请求体是文件字节，函数校验后写入 Blob |
| `POST /api/upload?direct=1` | 需要 | 直传：返回预签名 PUT 地址，浏览器把字节直接发给 Blob |
| `GET/DELETE /api/blobs` | 需要 | 列出 / 删除已上传的图片 |
| `GET /img?key=…` | **公开** | 从 Blob 读图并对外提供 |

### 为什么默认走代理上传，而不是文档推荐的直传

直传的好处是字节不经过函数，没有请求体大小限制。代价是浏览器要往另一个域名发跨域
`PUT`，会先触发 CORS 预检——而 Blob 的签名地址是否返回可用的 CORS 响应头，
**文档没写，本地也验不了**。万一不返回，上传在浏览器里必然失败，且是改不了的。

代理上传是同源请求，不存在这个变量，还顺带换来两件事：

1. 服务端能真正**限制大小**（预签名地址签不进体积约束，签发之后服务端就管不了了）；
2. 服务端能**校验文件头**，确认它真的是那个格式，而不是改了后缀的别的东西。

所以代理是主路径，超过 **4 MB** 才自动改走直传。`tests/blob-upload-test.js` 用真实
文件头样本覆盖了第 2 点（含 12 种交叉误判、RIFF-但-非-WebP、SVG/HTML 文本冒充图片等）。

> ⚠️ **4 MB 这个数是保守估计，不是查到的官方数字**——EdgeOne 没公布函数请求体硬上限。
> 真实上限若更低，超标文件会在到达函数之前被平台拒掉（表现为网关错误，而不是接口返回的 413）。
> 调大之前先拿一个接近上限的文件实测。
>
> ⚠️ **直传那条路从未被实际验证过**（就是上面 CORS 那个原因）。前端已经把这种失败
> 单独识别出来并提示「可先把图压到 4 MB 以内」，但真要用大文件，请先实测一次。

### `/img` 的两个刻意选择

- **不放在 `/api/` 下面**：`edgeone.json` 给 `/api/*` 设了 `cacheTtl: 0`，
  放进去等于每次都回源，正好把内容哈希键名带来的长缓存收益全部抵消掉。
- **键名正则是访问控制，不是输入清洗**，别放宽：
  ```js
  /^img\/[0-9a-f]{32}\.(png|jpg|webp|gif)$/
  ```
  它把 `/img` 限制成「只能读 `img/` 前缀下的内容哈希对象」。以后往同一个桶里放了别的
  东西（草稿、备份、任何私有数据），也不会因为存在这个公开路由而被人凭键名读出去。
  放宽成 `img/*` 或允许任意键，等于把整个桶变成公开只读接口。

### 部署后必须先验的一件事

**`/img` 的缓存键是否包含查询串。** 这个路由靠 `?key=` 区分不同的图，
如果 CDN 的缓存键只算路径不算查询串，那么所有图片会共用一份缓存、**互相串图**。
业界默认是算查询串的，`edgeone.json` 里也据此给 `/img` 配了一年 TTL——但这条我验不了，
而它错了的后果很显眼，所以请务必先做这个两分钟的验证：

1. 上传两张**明显不同**的图，记下各自的 `/img?key=…`；
2. 在同一个浏览器里先后打开这两个链接（不要用无痕，要让缓存生效）；
3. 刷新几次，确认**两个链接始终显示各自的图**。

若发现串图，把 `edgeone.json` 里 `/img` 那条 `caches` 规则删掉再试；
仍然串图说明必须改成路径式路由（`/img/<key>`），届时再动。

### 配额与清理

内容哈希键名意味着**换图不会顶掉旧图**——旧对象会一直留着。所以有两层清理。

#### 自动：保存内容时回收不再被引用的图

`POST /api/content` 写入成功后会顺手删掉「上一版引用过、这一版不再引用」的 Blob 对象，
不需要手动操作。响应体里会带回结果（没有可删的就不带 `gc` 字段）：

```json
{ "ok": true, "gc": { "deleted": ["img/<hash>.png"] } }
```

三条不能改的规矩，改之前请先想清楚：

1. **先写 KV，再删 Blob。** 反过来一旦 KV 写失败，图已经没了而线上内容还在引用它，
   这是不可恢复的。现在这个顺序最坏只留下一个孤儿对象，可以手动清。
2. **按整份内容做集合差，不按字段逐个比。** 同一张图在首页和历史页会共用一个键
   （内容哈希的必然结果），只从一处移除时对象仍在使用中。逐字段 diff 会删掉还在用的图。
3. **只删「曾经被引用过、现在不再引用」的键，绝不扫桶找未引用对象。** 管理员上传完图片
   还没点保存时，对象已经在桶里但不在 KV 里；按未引用扫桶会把它当垃圾删掉。
   **少清一个是浪费，多删一个是事故。**

回收失败（Blob 不可用、限频、删除报错）**不会**让保存失败——内容已经落盘了，
这时响应里的 `gc` 会带 `error` / `failed` / `pending` 如实说明没删掉什么。
单次最多删 50 个，超出的部分报在 `gc.pending` 里，不静默丢弃。

#### 两个会触发批量删除的按钮

「数据」页有两个动作会一次性让很多图失去引用，都必须先过确认弹窗：

| 动作 | 弹窗说什么 |
|---|---|
| 导入并应用 | 先在客户端算出**具体会删几张、键名是哪些**（最多列 5 条，其余报「另有 N 张」），再问 |
| 恢复默认 | 默认内容全是外链，等于删掉**所有**上传过的图，弹窗点明不可撤销 |

导入的数量是客户端算的，`assets/admin.js` 里有一份 `collectBlobKeys`，
与 `functions/api/content.js` 的那份**必须保持一致**（`BLOB_KEY_RE` 也一样）。
`tests/blob-key-parity-test.js` 把两个真实文件里的实现都切出来跑同一批语料对撞，
改任何一边之前先跑它。

> 弹窗**无条件出现**，不由「算出来是 0 张」决定问不问。万一两份实现跑偏，
> 最坏只是数字不准，不会退化成「不提示就把图删了」。

> 另外：导入前会挡掉非对象、以及既没有 `home` 也没有 `archive` 的 JSON。
> 不挡的话 `deepMerge` 遇到非对象会原样返回默认值——导入一个 `123`
> 就静默等于「恢复默认」，连带删掉所有上传的图。

> ⚠️ **已知竞态**：两个管理员同时编辑时，A 移除某图并保存会删掉对象，而 B 那份仍
> 引用它的旧快照保存后会得到一张失效图片。后台已经把保存串行化，但那只防同一个
> 浏览器。这个站是单人维护，所以按可接受处理；真要多人协作得加版本号做乐观锁。
> 补救办法是把原图重新上传一次——内容哈希键名保证键不变，引用会自动复活。

#### 手动：清理上传了却从未用上的孤儿

自动回收碰不到「上传完没保存就换了别的图」这类对象。「数据」页**最下面**有一张
「Blob 图片」卡片负责这一层：列出桶里的全部图片，标出每张是否还被内容引用，
可以复制链接或删除。也可以绕过界面直接发请求：

```bash
curl -H "X-Admin-Token: <你的口令>" https://<域名>/api/blobs
curl -X DELETE -H "X-Admin-Token: <你的口令>" "https://<域名>/api/blobs?key=img/<hash>.png"
```

面板有三个约束是官方文档决定的，不是随便挑的（见文档「列出对象」一节）：

- **没有「按时间倒序」**。`store.list()` 每条只回 `{ key, etag }`，**既没有大小也没有
  时间戳**，所以排不了序，界面按键名排。想按时间排就得自己另存一份元数据。
- **`list()` 不接受 `limit`**，能传的只有 `prefix` / `directories` / `paginate` / `cursor` /
  `consistency`。截断是服务端拿到全量之后自己切的（上限 500 条），超了会在面板上说明。
- **正在被引用的图，删除按钮是禁用的，不是弹个确认。** 删了就等于让线上内容指向一张
  失效图片，而这里没有任何非要现在删它的理由——正确做法是先把那个字段换成别的图，
  保存时[自动回收](#自动保存内容时回收不再被引用的图)会把它收走。

> 「引用中」的判定用的是本地这份 `data`，也就是**上次加载/保存后的内容**。
> 别人刚改过还没同步到你这边时，判定可能偏旧——所以它只用来禁用删除（偏保守），
> 不用来自动删任何东西。

#### 选图：按钮 + 弹窗，不是输入框

每个图片字段是一行三个控件：**选择图片**（打开上面那份图片集挑一张）、
**上传**（选本地文件，仍然可用）、以及一行说明当前值的文字
（`未选择图片` / `Blob · <短键名>` / `外部链接 · <域名+路径>`）。

原来那个 URL 输入框还在，只是 `display: none`——它仍然是**唯一的值载体**。
两条路径写值都走同一个动作：

```js
input.value = value;
input.dispatchEvent(new Event('input', { bubbles: true }));
```

这样 `hydrateForm` / `updateValue` / `updatePreview` / 导出 / 保存**一行都不用改**，
也不会出现「界面显示一张、存下去另一张」。改这块时请保持这个约定：
**任何新的写入方式都必须派发 `input` 事件，不要直接改 `data`。**

> 为什么不干脆删掉输入框：站点默认内容全是 hdslb 外链，图片集里根本没有它们。
> 删掉输入框就等于**没法再填外链**，也没法把默认值原样保存回去。
> 用 `display: none` 而不是 `type="hidden"`，是为了让它同时退出 Tab 序列和无障碍树。

> 删掉的对象在 `/img` 上还会被 CDN 缓存一年（键名声明了 `immutable`）。这不是 bug：
> 内容哈希键名不会被复用，缓存里那份不会张冠李戴，只是「已删除」不会立刻在公开路径上生效。
> 要立刻消失得去控制台刷缓存。

### 出错时怎么认

| 现象 | 大概率原因 |
|---|---|
| 上传报「Blob 凭据未注入：项目 ID 为空」 | 构建没执行 `npm install`，见 §5 第 4 步 |
| `/img` 与上传接口一律 500，且无具体话术 | 依赖没装上，模块导入就失败了（函数根本没跑起来） |
| 上传报「文件内容不是 image/png（文件头对不上）」 | 文件后缀被改过，实际不是这个格式 |
| 上传报「直传被浏览器拦下」 | 就是上面说的 CORS 未验证问题，先把图压到 4 MB 以内 |
| 图片能上传、`/img` 却 404 | Blob 默认读带 CDN 缓存的域名，刚写入可能还没同步；函数已自动用强一致域名重试一次，若仍 404 才是真没写进去 |
